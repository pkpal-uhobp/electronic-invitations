## 16. Обработка отсутствующих объектов

В проекте отсутствующий объект обрабатывается во view-функции. Например, для страницы отдельного события используется файл `events_web/views.py`.

```python
def event_detail(request, event_id: int):
    event = find_event_by_id(load_events(), event_id)

    if event is None:
        raise Http404('Событие не найдено')

    event_date = date.fromisoformat(event.date)

    return render(request, 'events_web/event_detail.html', {
        'page_title': event.name,
        'event': event,
        'event_date': event_date,
        'is_upcoming': event_date >= date.today(),
    })
```

Сначала функция `load_events()` загружает события из файла `data/events.json`. Затем функция `find_event_by_id()` ищет событие с переданным идентификатором.

При открытии адреса `/events/1/` Django передаёт во view значение `event_id = 1`. Если событие существует, оно передаётся в шаблон, и пользователь получает страницу с HTTP-статусом `200 OK`.

Если открыть адрес `/events/999/`, событие с таким идентификатором не будет найдено. Функция поиска вернёт значение `None`, после чего выполнится:

```python
raise Http404('Событие не найдено')
```

Django вернёт страницу с HTTP-статусом `404 Not Found`.

Использование `Http404` необходимо для того, чтобы:

- не отображать страницу с неверными данными;
- корректно сообщать пользователю об отсутствии объекта;
- не допускать ошибки сервера `500`;
- возвращать правильный HTTP-статус.

Аналогично обрабатываются отсутствующие приглашения, гости и организаторы:

```python
if invitation is None:
    raise Http404('Приглашение не найдено')
```

```python
if guest is None:
    raise Http404('Гость не найден')
```

```python
if user is None:
    raise Http404('Организатор не найден')
```

В данном проекте используется JSON-хранилище, поэтому применяется ручная проверка результата поиска. При использовании Django ORM можно было бы применить функцию `get_object_or_404()`.

## 17. Ошибка маршрутизации и ошибка поиска объекта

Ошибка маршрутизации и ошибка поиска объекта могут приводить к одинаковому HTTP-статусу `404`, однако возникают на разных этапах обработки запроса.

### Ошибка маршрутизации

Ошибка маршрутизации возникает, когда Django не может найти подходящий маршрут в файле `urls.py`.

Например, пользователь открывает адрес:

```text
/wrong-address/
```

В корневом файле `inviteweb/urls.py` такого маршрута нет:

```python
urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('homepage.urls')),
    path('events/', include('events_web.urls')),
    path('invitations/', include('invitations_web.urls')),
    path('users/', include('users_web.urls')),
    path('guests/', include('guests_web.urls')),
]
```

Django проверяет все маршруты, не находит совпадение и сразу возвращает HTTP-статус `404`. При этом ни одна view-функция не запускается.

Такая же ситуация возникает при открытии:

```text
/events/abc/
```

В файле `events_web/urls.py` используется конвертер:

```python
path('<int:event_id>/', views.event_detail, name='detail')
```

Он принимает только целые числа. Значение `abc` не является целым числом, поэтому маршрут не подходит, а функция `event_detail()` не вызывается.

### Ошибка поиска объекта

Ошибка поиска объекта возникает после того, как маршрут был успешно найден.

Например, адрес:

```text
/events/999/
```

соответствует маршруту:

```python
path('<int:event_id>/', views.event_detail, name='detail')
```

Django запускает функцию:

```python
event_detail(request, event_id=999)
```

Затем функция пытается найти событие:

```python
event = find_event_by_id(load_events(), event_id)
```

Если события с таким идентификатором нет, функция возвращает `None`, после чего view вызывает:

```python
raise Http404('Событие не найдено')
```

В этом случае маршрут существует, но сам объект отсутствует.

| Адрес | Результат |
|---|---|
| `/wrong-address/` | Маршрут не найден, view не запускается |
| `/events/abc/` | Параметр не соответствует `<int:event_id>` |
| `/events/999/` | Маршрут найден, объект не найден |
| `/events/1/` | Маршрут и объект найдены, ответ `200 OK` |

Главное различие заключается в следующем:

- ошибка маршрутизации связана со структурой URL;
- ошибка поиска объекта связана с отсутствием данных по правильному URL.

При включённом режиме `DEBUG=True` Django показывает подробную информацию о возникшей ошибке.

# Вопрос 18. Ошибка поиска шаблона и ошибка внутри шаблона

В проекте HTML-страницы формируются с помощью функции `render()`:

```python
return render(
    request,
    'events_web/event_list.html',
    {
        'page_title': 'События',
        'events': event_list,
    }
)
```

Перед формированием ответа Django выполняет несколько действий:

1. получает путь к шаблону;
2. ищет файл в каталогах шаблонов;
3. открывает найденный файл;
4. проверяет синтаксис Django Template Language;
5. передаёт в шаблон контекст;
6. формирует итоговый HTML-код.

Ошибки `TemplateDoesNotExist` и `TemplateSyntaxError` возникают на разных этапах.

## Ошибка TemplateDoesNotExist

`TemplateDoesNotExist` означает, что Django не смог найти файл шаблона по указанному пути.

Правильная структура файла в проекте:

```text
events_web/
└── templates/
    └── events_web/
        └── event_list.html
```

Поэтому в `events_web/views.py` используется путь:

```python
return render(
    request,
    'events_web/event_list.html',
    context
)
```

Если временно заменить его на:

```python
return render(
    request,
    'events_web/not_found.html',
    context
)
```

Django начнёт искать файл:

```text
events_web/templates/events_web/not_found.html
```

Если такого файла нет, появится ошибка:

```text
TemplateDoesNotExist
```

При `DEBUG=True` Django показывает подробную страницу ошибки и список каталогов, в которых выполнялся поиск.

### Причины TemplateDoesNotExist

- неправильное имя файла;
- ошибка в пути к шаблону;
- отсутствие файла;
- неправильная структура папок;
- приложение не добавлено в `INSTALLED_APPS`;
- значение `APP_DIRS` установлено в `False`.

В проекте поиск шаблонов приложений разрешён настройкой:

```python
'APP_DIRS': True
```

### Как исправить

Нужно проверить:

1. существует ли файл шаблона;
2. совпадает ли путь в `render()` со структурой каталогов;
3. правильно ли указано имя Django-приложения;
4. добавлено ли приложение в `INSTALLED_APPS`;
5. включена ли настройка `APP_DIRS`.

Правильный вариант:

```python
return render(
    request,
    'events_web/event_list.html',
    context
)
```

## Ошибка TemplateSyntaxError

`TemplateSyntaxError` означает, что Django нашёл файл, но не смог разобрать его содержимое из-за ошибки в синтаксисе шаблона.

Корректный цикл:

```django
{% for event in events %}
    {% include 'events_web/includes/event_card.html' %}
{% empty %}
    <div class="empty-state">Событий нет</div>
{% endfor %}
```

Если удалить закрывающий тег:

```django
{% endfor %}
```

Django выдаст:

```text
TemplateSyntaxError
```

Другой пример ошибки:

```django
{% if event %}
    <h1>{{ event.name }}</h1>
```

В этом коде отсутствует закрывающий тег `{% endif %}`.

Исправленный вариант:

```django
{% if event %}
    <h1>{{ event.name }}</h1>
{% endif %}
```

### Возможные причины TemplateSyntaxError

- незакрытый блок `{% for %}`;
- незакрытый блок `{% if %}`;
- неправильное написание `{% include %}`;
- ошибка в кавычках;
- отсутствие закрывающих символов `%}`;
- неизвестный тег или фильтр;
- неправильное использование переменной шаблона.

## Главное отличие ошибок

| Ошибка | Что произошло | На каком этапе возникает |
|---|---|---|
| `TemplateDoesNotExist` | Django не нашёл файл | При поиске шаблона |
| `TemplateSyntaxError` | Файл найден, но его код неправильный | При разборе содержимого |

Простая формулировка для защиты:

> При `TemplateDoesNotExist` проблема находится в имени или расположении файла. При `TemplateSyntaxError` файл найден, но внутри него есть ошибка синтаксиса Django-шаблонов.

## Что показать на защите

1. Открыть файл `events_web/views.py`.
2. Показать вызов:

```python
return render(request, 'events_web/event_list.html', context)
```

3. Открыть папку:

```text
events_web/templates/events_web/
```

4. Показать существующий файл `event_list.html`.
5. Временно заменить имя шаблона на `events_web/not_found.html`.
6. Открыть `/events/` и показать `TemplateDoesNotExist`.
7. Вернуть правильное имя шаблона.
8. Временно удалить `{% endfor %}` из шаблона.
9. Обновить `/events/` и показать `TemplateSyntaxError`.
10. Вернуть `{% endfor %}` и убедиться, что страница снова работает.

После демонстрации обязательно восстановить правильный код.
