## 3. Административная панель

В `users_web/admin.py`, `guests_web/admin.py`, `events_web/admin.py`, `invitations_web/admin.py` зарегистрированы соответствующие модели и настроены ModelAdmin. Поиск по названиям, именам, email и связанным полям; фильтрация по статусу и дате; столбцы и сортировка; связанные inline-объекты. Приложения и поля локализованы на русский язык. URL: `/admin/`. Для входа используется Django auth (не `users_web.User`).

**Скриншот 1:** основной список моделей Django Admin. **Скриншот 2:** список приглашений с поиском/фильтром. **Скриншот 3:** карточка события со связанными приглашениями.

## 4. Изменения модели и миграции

`Event`: добавлены уникальный транслитерированный `slug` и вычисляемый на стороне SQLite `name_length = Length(name)` через `GeneratedField(db_persist=False)`; миграции `0002`, `0003` для старых slug и `0004`. В `Invitation` введён `TextChoices` для статусов active, cancelled, completed, добавлены методы `InvitationQuerySet` и ограничение на повторные активные приглашения для связанного гостя/события; в модели не было отдельного `is_cancelled`, поэтому удалять/переносить его не понадобилось. Добавлены миграции verbose_name во все предметные приложения.

## 5. ORM и пользовательские сценарии

`invitations_web/views.py`: поиск через `Q`, фильтрация, безопасная сортировка, `Paginator`, статистика через `Count`/`annotate`, выбор последних записей через `F` и `values`. `events_web/views.py`: страницы по slug, сохранение ID-маршрута, поиск по дате, доступность гостей с учётом только активных приглашений. `events_web/context_processors.py`: `site_name` и число событий в общем шаблоне.

**Скриншот 4:** фильтр и пагинация. **Скриншот 5:** статистика с завершёнными приглашениями. **Скриншот 6:** URL события со slug.
